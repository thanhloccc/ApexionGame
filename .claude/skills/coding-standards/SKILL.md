## The rule that catches everyone

> **Do not write comments or XML docs unless the Project Owner asks for them.**
> **Do not touch existing comments** in files you edit. Leave them exactly as they are.

This covers `//`, `/* */`, section dividers, and every XML doc tag. Writing helpful explanatory
comments is the default instinct in most codebases and it is **wrong here**.

Always allowed, no permission needed:

- `// SAFETY:` above an `unsafe` block — **required**, and must explain why *this specific* operation
  is sound
- license headers and attribution on vendored or ported files
- `<auto-generated>` markers from build tools
- `#region` / `#endregion`

Full rule and the shape of XML docs when they *are* requested: `references/comments-and-async.md`.

## The five that bite most often

1. **Braces on every control block.** No exceptions — not for a single `return`, not for `count++`.
2. **`== false`, not `!`** in conditions. `if (list.IsEmpty() == false)`.
3. **Blank line above and below any statement that opens a scope**, except where blocks touch by
   design (`if`/`else`, `try`/`catch`) or the block starts/ends its parent scope.
4. **Leading-comma wrapping** for long parameter and argument lists, `)` on its own line.
5. **`=>` on a new indented line** for expression-bodied methods and properties. Inline is fine for
   accessors, lambdas and switch arms.

## Quick checklist (§14, condensed)

Before handing off any C# file:

**Format** — 4-space indent, LF, final newline · braces on their own line and on *all* control
blocks · blank line around block-scoped statements · ≤100 cols, 120 hard · no column alignment ·
spaces after commas and around operators · each `where` on its own line · leading-comma wrapping ·
field groups `const` → `static readonly` → `static` → instance.

**Style** — `== false` over `!` · no empty control blocks · flatten nested ifs · `goto FAILED` for
early exit in parse/validate · `for` with cached count where an indexer exists · `static` lambdas ·
**no new comments or XML docs**.

**Types & APIs** — `readonly struct` for small values · `[WrapRecord] readonly partial record
struct` for ids · capability interfaces over ad-hoc members · full `IEquatable<T>` pattern with
Ordinal string compares and `HashCode.Combine` · `T item` / `in T item` overload pairs · `readonly`
on non-mutating struct methods · failures return `Option<T>` or `bool TryXxx` — **never `null`,
never throw for an expected failure** · no public API change for style alone.

**Attributes & async** — `[MethodImpl(AggressiveInlining)]` per §11, on the *accessor* not the
property · cold paths (`ThrowXxx`, `CreateException`, logging) get `NoInlining` · `Async` suffix ·
`CancellationToken token = default` last · never swallow `OperationCanceledException` · log through
the project's logging module, never `UnityEngine.Debug` directly · `// SAFETY:` above every `unsafe`
block.
